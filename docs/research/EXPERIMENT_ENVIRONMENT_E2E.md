## Acceptance and method

Exercise the actual public HTTP and browser interfaces using isolated workspaces,
real explicitly selected providers and independent expected invariants. Preserve
original attempts and source attribution; diagnose any failure before changing code.
Completion is separate from meaningful task achievement and interpretation quality.
These are public DEVELOPMENT cases, not held-out capability or intelligence tests.

- All twelve installed environment families: validate/save, explicit live participant
  step/start, inspect recorded decisions/consequences/costs, export and zero-call replay.
- Matched conditions retain configured differences; revisions remain immutable.
  Pause commits in-flight work without duplicate sampling; restart does not resume it.
- Reusable mechanics: extract/create/rebind, two independent experiments, optimistic
  stale-update rejection, update/delete with unchanged pinned run evidence.
- Direct and tool-using participants, private ACLs/observations and actual read receipts.
- Separately billed declared adjudication and cutoff-scoped evidence interpretation.
- Finite new mechanics: independently frozen complete external oracle, explicit bounded
  generation, real containment/admission, reusable environment and run/replay. Generated
  prose/self-tests cannot replace the external oracle or authorize execution.
- Actual desktop/light and phone/dark browser creation/library/run/evidence flows;
  second-lifetime public state/export equality and provider-disabled replay.

Freeze resolved protocols and their expected checks before dispatch. Participant
choices are free: refusal, abstention or poor coordination are not app failures.
An invalid provider response, unsupported proposal or failed admission remains failed.
Do not silently retry, substitute models, raise limits or weaken a check.
